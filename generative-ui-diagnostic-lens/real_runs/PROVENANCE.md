# Provenance of the real Fluxion run output (slice 2, step 0)

The file `fluxion_standard_report.json` in this folder is a **byte-for-byte
copy of a completed Fluxion run's output**.  It is not a fixture, not
synthetic and not generated by this POC.

| item | value |
|---|---|
| artifact | `tests/reference_data/results_v1/standard_report.json` |
| upstream repository | the Fluxion clone (`anchapin/fluxion`), branch `develop` |
| introduced by | commit `31c038e3` - "feat(report): versioned standard results report v1 (#4104)", merged as `30a13ba6` (PR #4606) |
| sha256 | `1d783a1eba6f3ca621ad846d0fa15ee04e3033297b89c75d557a22f3c7c1146b` (identical in the upstream clone and in this copy) |
| schema | `schemas/results_v1.schema.json`, `schema_version` 1.0.0 |
| emitting engine | Fluxion engine, `tool_version` 1.0.0 |
| model | `model_name` "Untitled Simulation", `model_source` `model-file:examples/minimal.flux` |
| run period | label "annual", 1 year, 8760 timesteps of 3600 s |
| what the run produced | annual end-use energies and peaks, twelve monthly bins, unmet-hours accounting for the occupied and all-hours conventions, and a reference (sha256 checksum) to the hourly end-use series |

## How it was obtained (read-only)

The upstream file was read from the local Fluxion clone and copied; nothing
in Fluxion was executed, modified or written:

```
git -C ~/workspace/fluxion show develop:tests/reference_data/results_v1/standard_report.json
cp ~/workspace/fixtrees/fluxion-worker-4606-fix/tests/reference_data/results_v1/standard_report.json \
   generative-ui-diagnostic-lens/real_runs/fluxion_standard_report.json
```

The two copies were compared with `sha256sum` and are byte-identical.

## What the report is *not*

* It is **not** the issue #37 premise shape (`run_id`, `status`, solver
  block, inputs, provenance, log lines, table of result fields).  No JSON
  file anywhere in the Fluxion clone carries that shape - a read-only
  search of the clone found **no** JSON document containing a `"run_id"` or
  a `"fields"` key (`grep -rlE '"run_id"|"fields"' --include=*.json .`,
  excluding `target/`).  The fixture shape used in slice 1 is therefore a
  *shaped* premise, not a copy of an artifact that exists in the repo.
* The hourly end-use series is **not** embedded in the report: the report
  carries its sha256 checksum only.  The lens therefore has no hourly
  values to draw and renders "no data" for that view - it must not invent
  the series.
* The report carries **no log lines** and **no run inputs**, so the
  LogTail view of the real run is an explicit refusal (`no_log_field`).
* `annual.eui_kwh_per_m2` is left out of the lens' field manifest: the
  closed catalog's unit vocabulary has no `kWh/m2`, and a field whose unit
  the lens cannot canonicalise cannot be unit-checked.

## The lens' field mapping

`manifest.py` maps the report to lens field names mechanically
(`STANDARD_REPORT_FIELDS`): every lens field name is a field the report
carries, and every unit is the unit the report's own schema declares.
The mapping is one line per field and is quoted in full in
`../manifest.py`.
