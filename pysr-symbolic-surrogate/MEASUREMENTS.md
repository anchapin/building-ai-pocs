## PySR arm — environment failure record (supervisor, 2026-11-13)

Every PySR fit in this VM failed before producing an equation; the failure was
diagnosed in three stages, each stage's fix verified before the next attempt:

1. `OSError(28, 'No space left on device')` on every fit. Root cause: juliapkg
   stages the Julia 1.11.9 download (273.2 MB tarball) in the system temp dir;
   this VM's `/tmp` is a 512 MB tmpfs, so extraction/staging overflows it and
   the Julia install never persists (each new process re-downloaded it).
2. With `TMPDIR` pointed at the workspace disk, the install persisted:
   `julia_env` = 994 MB on disk, download complete and verified.
3. Fits then fail with a bare `AssertionError()` from the juliacall boundary,
   and a minimal direct fit (100 points, niterations=5) dies silently right
   after the Julia install step with no traceback — consistent with the Julia
   backend being killed during SymbolicRegression.jl precompile under this
   VM's memory cap (6 GB shared). No PySR equation, RMSE, or wall-clock exists
   for this slice; none is estimated or invented here.

Environment cost measurements: `pip install pysr==2.7.2` (+ numpy / scikit-learn
/ juliacall / juliapkg) into the folder venv ≈ 452 MB before Julia; Julia
download 273.2 MB; installed `julia_env` 994 MB; one full install attempt
≈ 4–12 min wall-clock on this VM depending on download speed.

Reproduction note for the next slice: run the PySR arm with `TMPDIR` on a
large disk and enough RAM for Julia precompilation (the desktop runner is the
natural host); the runner (`src/run_measurements.py --arms ls-refit,pysr
--control-arm`) needs no code change.
